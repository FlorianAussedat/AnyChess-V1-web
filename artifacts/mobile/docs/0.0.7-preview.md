## Compatibilité interversions

Le moteur, les 18 clés et les formats de synchronisation ne sont pas modifiés. Les tests utilisent deux moteurs complets et deux stockages locaux indépendants avec le véritable adaptateur REST `SupabaseCloudRemote`, un propriétaire commun et un serveur HTTP simulé en mémoire avec contrôle de révision. Aucun socket ou compte distant réel.

Vérifié : créations distinctes portant le même nom, dossiers imbriqués, variantes/commentaires/NAG, échanges dans les deux sens, profil/langue/records, édition hors ligne conservée après redémarrage puis reprise en données mobiles, identifiants stables et absence de nouvelle copie lors de synchronisations répétées.

**Limite existante démontrée :** deux contenus PGN différents pour le même identifiant produisent une copie de récupération stable, y compris après certaines éditions successives. La fusion conservatrice ne distingue pas toujours ancien contenu et conflit simultané. Les tests contrôlent les contenus, le nombre et la stabilité de ces copies. Une exigence stricte de zéro copie après édition nécessiterait un chantier séparé ; aucune modification du moteur de fusion dans cette PR.

**Anciens clients : utilisation simultanée non validée et déconseillée sur un compte réel.** Un ancien upsert inconditionnel peut écraser le document distant même si `revision` existe. Un test démontre ce risque en mémoire. La colonne seule ne garantit pas un CAS universel et il n'existe pas de transaction couvrant les 18 documents. Identifier le code/protocole des APK réellement installées avant usage croisé. Les snapshots PR #127/#128 sont locaux et ne transitent pas entre packages.
